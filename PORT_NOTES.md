# CodeChickenLib 26.3 downstream migration notes
Target Minecraft 26.3 / NeoForge 26.3.0.118 / Java 25; candidate 4.6.1.1. Source compatibility guide, not a claim of binary compatibility or release acceptance. Upstream comparison: 5b35f50d2f25f4ced359658eb0561f4c0aa07e6c.

## Primary migration boundaries
- Replace ResourceLocation with Identifier; existing CCL serialization method names remain where applicable. Use native registry keys and holders, not numeric IDs from another registry instance.
- Block entity overrides use ValueInput/ValueOutput. CCL modular data component callbacks retain nested CompoundTag format and obtain lookup context from serialization. Preserve the original component keys when migrating saved data.
- RecipeProvider uses registry bootstrap and standalone DataProvider paths. Use ItemStackTemplate for recipe results and custom factories; nonempty already-created ItemStack overloads convert to templates. Unlockable recipes must register before constructing the advancement, or use native RecipeOutput forward references. Native conditions and actual advancement IDs retained. Use addLootTables/addAllLootTables for modular loot registry bootstrap, rather than treating loot as ordinary DataProvider. Loot subproviders use LootTableSubProvider.Context.
- ItemModelProvider now emits both geometry models and items definitions. Parent references are Identifier, no ExistingFileHelper constructor. Class model loader accepts native ItemModel, UnbakedModel or UnbakedGeometry according to path. Class-backed native item model uses public no-arg constructor for identity bake, public Matrix4fc constructor for transformed bake. Composite item definition uses codechickenlib:item_composite, named children and optional item_render_order; explicit empty order remains empty. Legacy unknown predicate properties need explicit native range/condition mappings; generic using_item is not an exact substitute for all legacy predicates. Test the actual downstream property semantics.
- DynamicTextureProvider accepts ResourceProvider. GUI rendering now uses GuiGraphicsExtractor and deferred extraction. Preserve call order; do not retain a GUI VertexConsumer across flush. GUI scissor/strata and real input behavior need in-game validation.
- VertexFormat and PrimitiveTopology are RenderPearl types. CCL CachedFormat.BLOCK is a logical editable format, not a terrain GPU buffer layout. Native BakedQuad is static geometry plus material/normal/color metadata. For per-vertex light use Quad.bakeWithInstance or BakedQuadVertexBuilder.bakeWithInstances and LitQuad.emit/instance. Native overlay is uniform per quad; nonuniform is rejected. Static bake() intentionally returns geometry only. Legacy normalized light and overlay arrays are coordinate/240; raw GPU pack/unpack uses the actual declared component representation.
- ICCBlockRenderer emits BlockQuadOutput with native BakedQuad and QuadInstance, per ChunkSectionLayer; null layer indicates breaking overlay. Entity callbacks use SubmitNodeCollector and fluid callbacks use FluidRenderer.Output. Old direct MultiBufferSource hooks cannot be reused. Embeddium 1.21 bridge disabled; no verified 26.3 replacement. Test custom block, fluid, breaking and entity render paths in game.
- IItemRenderer native item model update/submit replaces old ItemRenderer mixin interception. Use supplied pose, collector and light/overlay. Native layer centering is already applied; do not center geometry a second time. PerspectiveModelState supports a separate block transform and UV lock. Legacy WrappedItemModel and OverrideListModel use native model delegates; arbitrary custom override behavior needs downstream tests.
- CCRenderState.bind now accepts native render type and explicit VertexConsumer; configure UV3 glint coordinates when required. RenderUtils hitbox helpers take callback consumer instead of MultiBufferSource. Fluid pipeline registered with native regular and OIT event; visual behavior still needs verification.
- VBORenderType caches GPU buffers; prepareDraw outside render pass, submit within correct pass, close on render thread. Legacy CCShaderInstance is standalone OpenGL only, not a native RenderPipeline. Do not use within RenderPearl-managed pass. ShaderProgram/objects have explicit close; shader object owners close shared shaders separately. Resource reload uses provided manager and defers GL work.
- PacketCustom wire type and bytes unchanged; payload snapshot immutable by convention, handler packet lifetime ends after callback. Do not retain inbound buffers. Container packets verify menu identity and stillValid. Live network tests pending.

## Evidence and limitations
Native headless server-data and client-data tests passed. Unit tests cover serialization, model/quad transforms, datagen helpers, GUI grid geometry, shader parsing and packet snapshots. They do not prove actual GPU execution or graphical model baking. Later headless gameplay tests are summarized below. No normal dedicated-server EULA acceptance or graphical client launch occurred.

## Later compatibility additions (through model smoke 19)
- Native item-class models may implement ItemModel.Unbaked with a public no-arg constructor; a single delegate persists through resolve/bake. OrderedItem supports visibility. Explicit selectProperty and indexed native range/condition parameters are supported. Legacy time defaults daytime. Legacy bow pull is elapsed ticks / 20; crossbow pull uses native property. Verify actual gameplay predicate semantics.
- GUI item tint is per native atlas/PiP blit, not a change to model geometry. Native item resolution retains explicit world and owner context. Flat GUI entity preview scales logical depth independently of X/Y. Actual graphical output remains pending.
- WrappedItemModel ordinary layers can be mapped via the protected renderWrapped overload; native special model callbacks are not mapped. Preserve tint indices in mapped quads. Arbitrary legacy VertexConsumer callbacks require migration.
- BakedVertexSource.put(LitQuad) and put(BakedQuad, QuadInstance) retain instance light/overlay and color; coordinates are scoped during CCRenderState submission. Static geometry alone does not retain those channels.
- Custom fluid vertices require Position, Color, UV0 and UV2 for each vertex and complete quads on each layer. All batches are validated before native output; optional attributes are accepted. CCL declines before NeoForge native fallback, with duplicate evaluation suppressed for the same cell.
- ICCBlockRenderer layer arguments are logical material layers, even when native fast-leaf settings route geometry to an opaque physical buffer. A custom CUTOUT override replaces logical CUTOUT only; other material layers still submit normally. Context-aware canHandleEntity/renderEntity overloads receive BlockDisplayContext; old implementations delegate unchanged. Eligibility exception fallback leaves native state intact when enabled. Deferred collector submission is not transactional; arbitrary submission exceptions cannot safely replay vanilla. Native outline-only and Z-offset paths submit ordinary model parts, not special-renderer callbacks.
- Custom ShaderObject implementations recompiling in-place should override compilationRevision(). Standalone legacy GLSL processor supports inline native angle-bracket includes with conditional positioning; legacy imports remain hoisted. No claim of complete native pipeline or Vulkan shader compatibility.
- Atlas holders allocate on init, own registered texture only while still mapped, and preserve mod-scoped directory lookups and explicit cross-namespace references. Native CPU stitching tested; GPU reload remains pending.
- DataSync sends initial server sample and checks byte-index bounds; menu outbound packets release temporary buffers. Test real initial synchronization and negotiation with a connected client.

## Alpha validation (2026-11-27)
95 unit tests and six native server GameTests passed. The GameTests cover live block entity placement, prior-process disk NBT restoration, inventory transfer and equipment/drag interactions, data-sync retry, native packet codecs, and optional channel advertisement. The packaged client/server data-generation integration passed before the narrowly scoped DataSync retry fix. Full graphical, multiplayer negotiation, entire-world restart and independent production installation remain unverified. Test real dependent mods before relying on this alpha in production.
